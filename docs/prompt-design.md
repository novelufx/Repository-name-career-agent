# Prompt 设计文档

> 更新日期：2026-06-02

---

## 一、整体设计思路

CareerAgent 有五个 AI 任务，每个任务都有对应的 Prompt。这些 Prompt 的设计目标是：稳定、结构化、可执行、不空泛。

### 稳定性设计

所有 Prompt 都要求返回 JSON 格式，使用 `response_format: { type: "json_object" }` 参数。每个 Prompt 都包含明确的字段说明和示例，减少 AI 的自由发挥空间。

temperature 设置为 0.3-0.5，降低随机性。max_tokens 根据任务复杂度设置，避免输出被截断。

### 结构化输出

所有输出都设计为嵌套的 JSON 对象，方便前端直接解析和渲染。每个字段都有明确的类型说明（string、number、array、object）。

评分统一使用 0-100 的数值，分类使用枚举值（如 "strong" | "moderate" | "weak" | "missing"）。

### 避免空泛

要求 AI 给出具体的例子，而不是抽象的建议。要求 AI 引用用户输入的原文，证明分析是基于具体内容的。要求 AI 给出可执行的建议，而不是"建议提升能力"这种空话。

### 岗位特点

在 Prompt 中加入对 AI 产品岗位的理解：了解大模型原理、有 prompt 工程经验、懂 AI 产品的用户体验、能做效果评估。

在分析时关注：是否体现 AI 思维、是否有数据驱动的意识、是否有产品 sense。

## 二、Prompt 详细说明

### JD 分析 Prompt

文件位置：`src/prompts/jdAnalysisPrompt.ts`

这个 Prompt 的作用是分析职位描述，提取关键信息，帮助求职者快速理解岗位要求。

输入只有一个字段：`jdText`，用户粘贴的 JD 文本，长度 500-5000 字。

输出包括：岗位名称、公司、部门、工作地点、核心职责（3-7 条，每条不超过 20 字）、技能要求（区分必备和加分，标注要求水平）、经验要求、学历要求、薪资范围、高频关键词（5-10 个）、公司文化推测、一句话总结。

设计思路是要求从 JD 原文中提取信息，而不是自己编造。区分必备技能和加分技能，帮助用户判断优先级。提取高频关键词，方便后续简历匹配度分析。一句话总结帮助用户快速理解岗位核心要求。

### 简历匹配度诊断 Prompt

文件位置：`src/prompts/resumeMatchPrompt.ts`

这个 Prompt 的作用是评估简历与岗位的匹配度，找出差距，给出优化建议。

输入有两个字段：`resumeText`（用户输入的简历内容）和 `jdAnalysis`（JD 分析结果，来自任务一）。

输出包括：匹配度评分（0-100）、关键词匹配情况（已匹配、缺失、部分匹配）、每个技能的匹配程度（有证据和建议）、经历相关性分析、具体的优化建议（有优先级和示例）、一句话总结。

设计思路是匹配度评分有明确的计算规则：关键词 40%，技能 30%，经历 30%。每个技能的匹配程度都要有证据支撑，不能主观判断。优化建议必须是可执行的，有具体的示例。引用简历中的原文，证明分析是基于具体内容的。

### 项目经历优化 Prompt

文件位置：`src/prompts/projectOptimizePrompt.ts`

这个 Prompt 的作用是优化项目经历描述，使其更专业、更有说服力。

输入有两个字段：`projectDescription`（用户输入的项目经历描述）和 `jdAnalysis`（JD 分析结果，可选，用于针对性优化）。

输出包括：原始描述的分析（字数、是否有量化数据等）、优化后的描述、改进点分析（有前后对比）、新增的关键词、新增的量化数据、结构分析（STAR 法则）、针对不同岗位的替代版本。

设计思路是使用 STAR 法则（情境-任务-行动-结果）重写描述。如果提供了 JD，优先添加 JD 中的关键词。提供多个版本，针对技术岗和产品岗。每条改进都要说明为什么这样改更好。量化数据必须是合理的估算，不能夸大。

### 模拟面试 Prompt

文件位置：`src/prompts/interviewPrompt.ts`

这个 Prompt 的作用是生成面试问题和追问，模拟真实面试场景。

输入有五个字段：`resumeText`（用户的简历内容）、`jdAnalysis`（JD 分析结果）、`currentQuestion`（当前问题，追问时使用）、`userAnswer`（用户的回答，追问时使用）、`interviewHistory`（面试历史）。

输出包括：问题内容、问题类型（技术/行为/情景/追问）、难度（简单/中等/困难）、问题分类、考察意图、回答要点、参考答案、可能的追问、回答时的雷点。

设计思路是第一个问题从简历中的项目经历开始。问题类型分布：技术 40%，行为 30%，情景 30%。参考答案基于用户的简历内容，不是通用答案。指出回答时的雷点，帮助用户避免踩坑。支持追问，根据用户的回答进行针对性引导。

### 面试反馈报告 Prompt

文件位置：`src/prompts/feedbackPrompt.ts`

这个 Prompt 的作用是生成综合评估报告和行动计划。

输入有五个字段：`resumeText`（用户的简历内容）、`jdAnalysis`（JD 分析结果）、`resumeDiagnosis`（简历诊断结果）、`projectOptimization`（项目优化结果）、`interviewHistory`（面试历史）。

输出包括：综合评分（0-100）、五个维度的评分（技术能力、项目经历、沟通表达、问题解决、岗位匹配度）、优势领域（有证据和展示建议）、待提升领域（有改进行动和时间规划）、面试表现分析、可执行的行动计划（按优先级排序）、3-5 条具体的下一步建议。

设计思路是综合评分有明确的计算规则：简历 30%，项目 30%，面试 40%。五个维度覆盖全面，不能遗漏。优势和不足都要有证据支撑。行动计划必须是具体的、可执行的。所有建议都要结合 AI 产品实习生、产品实习生、软件工程实习生等岗位的特点。

## 三、Prompt 调用流程

整个流程是这样的：

用户输入 JD，调用任务一：JD 解析。

用户输入简历，调用任务二：简历匹配度诊断（结合 JD 解析结果）。

用户输入项目经历，调用任务三：项目经历优化（结合 JD 解析结果）。

用户进入模拟面试，调用任务四：模拟面试问题生成（结合简历和 JD）。

用户回答后，生成追问或新问题。

面试结束后，调用任务五：面试反馈报告生成（综合所有结果）。

## 四、技术实现要点

### API 调用配置

```typescript
const defaultOptions = {
  temperature: 0.3,
  max_tokens: 2000,
  response_format: { type: "json_object" }
};
```

### 错误处理

如果 AI 返回的 JSON 解析失败，重试一次。如果仍然失败，返回默认的错误提示。

如果 AI 返回的字段缺失，使用默认值填充，而不是报错。

### 结果缓存

相同输入的结果可以缓存，避免重复调用 API。缓存 key 使用输入内容的 hash 值。

## 五、后续优化方向

### Prompt 优化

根据用户反馈，持续优化 Prompt，让分析更准确、建议更具体。

增加 few-shot 示例，让 AI 更好地理解期望的输出格式。

### 新增 Prompt

支持更多岗位类型的分析，如产品运营、数据分析、UI 设计。

支持更多场景，如薪资谈判、offer 选择、职业规划。

### 效果评估

收集用户对 AI 分析结果的反馈，评估 Prompt 的效果。

对比不同版本 Prompt 的效果，持续迭代优化。
