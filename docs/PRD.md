## 一、产品背景

### 1.1 问题发现

大三开始准备秋招的时候，我发现身边同学普遍面临几个问题：

- 简历投出去没回复：投了几十份简历，回复率不到 10%，不知道问题出在哪
- 不会写项目经历：明明做了不少东西，写出来却像流水账，不知道怎么突出亮点
- 面试准备靠刷面经：去牛客网看面经，信息太散，不知道怎么系统准备
- 找不到人帮忙改简历：学长忙、付费贵，ChatGPT 的回答又不太稳定

这些问题其实可以归结为一点：缺乏专业的求职指导。

### 1.2 为什么想做这个产品

我之前用 ChatGPT 改过简历，发现几个问题：

1. 每次都要重新描述背景，很麻烦
2. 得到的建议不稳定，换个问法结果就不一样
3. 需要自己设计 prompt，门槛有点高

所以我想：能不能做一个工具，把 JD 分析、简历诊断、项目优化、模拟面试这些步骤串起来，让用户像流水线一样完成求职准备？

### 1.3 产品定位

AI 驱动的求职简历优化与模拟面试助手。

把原本需要找学长或付费咨询的求职准备工作，用 AI 串联成一个完整的流程，让每个大学生都能获得专业的求职指导。

## 二、目标用户

### 2.1 主要用户

大学生求职者（大三/大四/研究生），年龄 20-25 岁，主要场景是秋招、春招、实习投递。他们技术背景，熟悉互联网工具，但缺乏求职经验，不知道怎么包装自己。

### 2.2 用户画像

**用户 A：技术型选手**

小张，大三，计算机专业，目标是大厂前端岗。技术能力不错，项目做了好几个，但简历写得像技术文档，HR 看不懂。他想把项目经历写得更专业、更有说服力。

**用户 B：转行选手**

小李，大四，非计算机专业，想转码找开发岗。自学能力很强，做了几个练手项目，但项目经历少，简历内容单薄。他想把手头的项目经历包装得更好。

**用户 C：海投选手**

小王，研究生二年级，大厂中厂都投。简历内容还行，但没针对性，同一份简历海投，回复率很低。他想知道简历和具体 JD 哪里不匹配。

### 2.3 用户规模

2026 届高校毕业生预计 1200 万以上，其中计算机相关专业约 100 万以上。每个人在求职季平均投递 30-50 份简历，市场需求真实存在。

## 三、用户痛点

### 3.1 核心痛点

| 痛点 | 严重程度 | 现有解决方案 | 不足 |
|------|----------|--------------|------|
| 不知道简历和 JD 哪里不匹配 | 高 | 找学长看 | 学长忙，反馈慢 |
| 项目经历写得像流水账 | 高 | 参考别人的简历 | 不知道怎么改 |

### 3.2 痛点分析

为什么会有这些问题？

求职指导资源不均衡，不是每个人都有学长帮忙。信息不对称，学生不知道 HR 和面试官在看什么。改简历、准备面试这些事情是割裂的，缺乏系统性。

AI 可以提供 7x24 小时的个性化指导，结构化的工作流可以把割裂的步骤串联起来，免费使用可以降低获取专业指导的门槛。

帮助用户提升简历质量，让简历更匹配 JD、更专业。提供系统性的面试准备，从 JD 分析到面试反馈形成完整链路。降低求职准备门槛，无需付费、无需找人。

## 五、核心使用流程

### 5.1 工作流设计

整个流程分五步：

第一步是 JD 解析，用户粘贴目标岗位的职位描述，AI 提取关键要求和技能。

第二步是简历诊断，用户输入简历内容，AI 评估匹配度，找出差距。

第三步是项目优化，用户输入项目经历描述，AI 优化表达，突出亮点。

第四步是模拟面试，AI 面试官提问，用户回答，获得即时反馈。

第五步是反馈报告，综合前面所有步骤，生成评估报告和行动计划。

### 5.2 流程设计原则

前一步的输出是后一步的输入，形成闭环。从分析到优化到练习，难度逐步提升。用户可以随时暂停，下次继续。用户也可以回到任意步骤重新操作。

### 5.3 用户旅程

用户带着"我想优化简历"的目标进入，看到五步工作流，理解整体流程。然后依次完成 JD 分析、简历诊断、项目优化、模拟面试，最后查看综合报告，获得行动计划，带着"知道怎么改进"的收获离开。

## 六、功能模块说明

### 6.1 功能列表

| 功能 | 优先级 | 说明 |
|------|--------|------|
| JD 解析 | P0 | 分析职位描述，提取关键要求 |
| 简历诊断 | P0 | 评估简历与 JD 的匹配度 |
| 项目优化 | P0 | 优化项目经历描述 |
| 模拟面试 | P0 | AI 面试官模拟面试 |
| 反馈报告 | P0 | 综合评估报告 |
| API 配置 | P0 | 设置 API Key 和模型 |
| 演示模式 | P0 | 无 API Key 时使用 mock 数据 |
| 工作流进度 | P1 | 显示当前步骤和完成状态 |
| 历史记录 | P1 | 查看历史分析结果 |

### 6.2 功能详细说明

**JD 解析**

用户粘贴职位描述，AI 分析并提取关键信息。输出包括岗位名称和公司、核心职责列表、必备技能要求、加分项技能、经验要求、薪资范围（如有）。

举个例子，小张看到一个前端岗位的 JD，想知道这个岗位到底要什么人，于是把 JD 粘贴进来，系统自动提取出关键要求。

**简历诊断**

根据 JD 分析结果，评估简历的匹配度。输入是简历内容和 JD 分析结果（自动传递），输出是匹配度评分（0-100）、关键词匹配情况、技能匹配分析、优化建议列表。

小张已经有了 JD 分析结果，现在想知道自己的简历和这个岗位有多匹配，于是输入简历内容，系统给出评分和具体建议。

**项目优化**

优化项目经历描述，让表达更专业、更有说服力。输入是项目原始描述，输出是优化后的描述、优化前后对比、改进点分析、新增关键词。

小张的项目经历写的是"使用 React 开发了 xx 系统"，系统帮他优化为"基于 React + TypeScript 架构，实现 XX 功能，首屏加载时间减少 40%"。

**模拟面试**

AI 面试官进行模拟面试，提供即时反馈。输入是用户的回答，输出是面试问题（技术/行为/情景）、回答评分、优点和改进建议、参考答案。

小张准备好了简历，想练习一下面试，于是进入模拟面试环节，AI 面试官根据他的简历和 JD 提问，他回答后获得即时反馈。

**反馈报告**

综合前面所有步骤，生成评估报告。输入是前四个步骤的数据（自动传递），输出是综合评分、分项评分、优势和待提升点、行动计划、推荐学习资源。

小张完成了所有步骤，想看看整体的准备情况，于是查看反馈报告，获得一份完整的评估和行动计划。

**API 配置**

用户配置自己的 API Key，连接 AI 服务。配置项包括 API Key、Base URL、模型名称。API Key 仅保存在本地浏览器，不配置则使用演示模式，支持小米 MiMo 和其他兼容 OpenAI 格式的 API。

**演示模式**

未配置 API Key 时，使用预设的 mock 数据演示功能。无需注册、无需配置，使用预设的分析结果，展示完整的产品功能，响应时间模拟真实场景。

## 八、用户故事

### 8.1 JD 分析

作为求职大学生，我希望粘贴 JD 后能快速了解岗位要求，这样我就知道这个岗位到底要什么人，不用自己一条条整理。

验收标准：支持粘贴任意格式的 JD 文本，自动提取岗位名称、职责、技能要求，区分必备技能和加分技能，分析结果结构化展示。

### 8.2 简历诊断

作为求职大学生，我希望知道简历和 JD 的匹配度，这样我就知道哪些地方需要改进，不用盲目修改。

验收标准：给出 0-100 的匹配度评分，列出已匹配和缺失的关键词，提供具体的优化建议，建议要可执行，不要空话。

### 8.3 项目优化

作为求职大学生，我希望把项目经历写得更专业，这样 HR 和面试官能看懂我的价值，不会觉得我在写流水账。

验收标准：提供优化前后的对比，解释为什么这样改，突出量化成果，新增相关关键词。

### 8.4 模拟面试

作为求职大学生，我希望有个人能陪我练习面试，这样我面试的时候不会太紧张，知道怎么回答问题。

验收标准：提供不同类型的问题（技术/行为/情景），对回答给出即时反馈，指出优点和改进点，提供参考答案。

### 8.5 反馈报告

作为求职大学生，我希望看到一份完整的评估报告，这样我就知道整体准备情况，知道下一步该做什么。

验收标准：综合前面所有步骤的结果，给出分项评分和整体评分，提供可执行的行动计划，推荐相关学习资源。

## 九、MVP 范围

### 9.1 MVP 包含

五个核心功能（JD 解析、简历诊断、项目优化、模拟面试、反馈报告），加上 API 配置和演示模式。

### 9.2 MVP 不包含

用户注册登录（降低使用门槛，先用 localStorage）、历史记录（MVP 阶段先不实现）、文件上传（先用文本粘贴）、流式输出（先用一次性返回）、多语言支持（先做中文）。

### 9.3 MVP 成功标准

五个核心功能可正常使用，演示模式能完整展示产品价值，用户能在 10 分钟内完成整个工作流，获得 10 个以上用户的真实反馈。

## 十、非功能需求

### 10.1 性能需求

页面加载时间控制在 2 秒以内，AI 响应时间控制在 5 秒以内，首屏渲染时间控制在 1 秒以内。

### 10.2 兼容性需求

支持 Chrome、Firefox、Safari、Edge 最新版本，支持 1280px 及以上宽度，桌面端优先，移动端基础适配。

### 10.3 安全需求

API Key 仅保存在本地浏览器，不上传服务器。用户输入的简历内容不持久化存储。API 通信使用 HTTPS。

### 10.4 可用性需求

首次使用 2 分钟内理解产品用法，单步操作 5 分钟内完成，提供清晰的错误提示和恢复建议。

## 十二、后续迭代方向

### 12.1 短期优化（1-2 周）

优化 Prompt，让 AI 分析更准确、建议更具体。优化结果展示，让分析结果更直观、更易理解。增加引导，新用户首次使用的操作引导。

### 12.2 中期扩展（3-4 周）

支持上传简历文件（PDF/Word）。保存用户的分析历史。支持更多岗位类型的分析。

### 12.3 长期规划（1-2 月）

用户系统，注册登录，数据云端同步。社区功能，用户分享简历模板、面试经验。付费功能，高级分析、无限次数。

### 12.4 技术优化

流式输出，实时显示 AI 生成内容。性能优化，减少加载时间，提升响应速度。多模型支持，支持切换不同 AI 模型。
